# Issue #8 — 部分的な観測からの参考評価（v0.5.0）

## 目的と範囲

最新main `85729d3`、AGENTS.md、開発計画、Issue #8/#9を確認。既存 `rdl.js` の角度による完成レップ検出と `motion-candidates.js` を変更せず、独立した `rdl-feedback.js` / `feedback-ui.js` を追加。膝・股関節が部分的でも、上体の前傾・復帰を読み取れる動作区間に参考指標と次のセットで試す助言を表示します。Issue #9の全面的な文言変更は別PRです。

従来の `estimateHinge` は股関節50%・体幹80%・4点以上の角度幅のみ表示していました。新レイヤーは局所的な観測角度と時間的位置を記録し、動作の上部・深い場面・戻りの根拠がそろう項目だけを使用します。角度はあくまで保存された画像面内のPose推定値です。精密な関節角度の実測と同一視しません。

## 2種類の割合

方式版：`rdl-observed-feedback-v1`。全て0〜1の係数を重み付けし、100倍して四捨五入。割合は動作パターンの参考指標で、フォームの正しさ、一致率、測定精度の確率ではありません。

### 共通の観測条件

- RDL、利用者が指定した撮影方向「横」、撮影側left/right。撮影設定を指定しただけでは実際の方向・遠近・カメラ位置の一致を証明しません。
- 0以上の開始時刻 < 深い場面の時刻 < 終了時刻。元の時系列は有限・厳密な昇順。並び替えで不正データを隠しません。
- 区間に6点以上。先頭/末尾の未取得時間、隣接記録の間隔は0.35秒以下。
- 上体の観測は区間の60%以上。上体の有限観測同士の間隔も0.35秒以下。
- 各角度は0〜180度の有限値。欠測を補間したり他関節から作ったりしません。
- 動作の上部：開始から区間長の20%。深い場面：保存されたbottom時刻の前後20%。戻り：終了前20%。それぞれ2点以上の観測が必要。境界点は両区間に含む場合があります。
- 各場面の値は、その場面で実際に取得できた推定角度の平均。少なくとも前傾変化5度が必要。5度はノイズを避ける実装上の閾値で、RDLの理想幅ではありません。

上体の開始平均をLstart、深い場面をLbottom、終了平均をLendとする。前傾変化 `L = Lbottom − (Lstart + Lend)/2`。上体観測幅 `W = 区間内の観測最大 − 観測最小`。

戻り係数 `R = clamp(1 − |Lend − Lstart| / max(W, 10°), 0, 1)`。開始と終了の上体傾きが近いほど大きい値です。股関節・膝の戻りや安全性を直接測る係数ではありません。

### A：前傾から戻る動きの目安

股関節/膝の3場面がそろわない場合などに使用。

`A = clamp(L / 45°, 0, 1)`

`割合 = round(100 × (0.6 × A + 0.4 × R))`

**45度は正規化のために固定した工学的尺度で、理想角度や文献上の推奨値ではありません。** 膝・股関節の欠測を補った「ヒップヒンジ点数」ではなく、観測した前傾・復帰の指標です。股関節主体かどうかは未評価。

### B：股関節中心の動きの目安

股関節と膝も3場面それぞれ2点以上読み取れ、股関節の変化Hが5度以上の場合。

`H = max(0, (股関節開始平均 + 終了平均)/2 − 深い場面平均)`

`K = |(膝開始平均 + 終了平均)/2 − 深い場面平均|`

`D = H / (H + K)`、`Ahip = clamp(H / 60°, 0, 1)`

`割合 = round(100 × (0.5 × D + 0.3 × Ahip + 0.2 × R))`

股関節の変化の比率、観測幅、上体の復帰を統合します。膝のKは角度の変化で、膝がどれくらい曲がった姿勢かそのものではありません。60度も工学的尺度です。欠測期間の実際の最大変化はわからず、観測の偏り・ノイズで割合が変わります。この方式は指導者による妥当性検証をまだ行っていません。

全体の割合は、計算できた区間が同じ方式の場合だけ、その割合の単純平均。方式が混在する場合は全体平均を保留し、区間ごとに異なる指標名を表示。採点不可の区間は分母に含めません。読み取れた区間数を併記します。

## 観測幅と助言

観測幅は2点以上で `最大 − 最小` を表示します。フォーム全体の可動域と断定せず、点数・局所割合・最初/最後の観測時刻・3場面の点数を併記。少数の角度があっても、必要な場面が欠けた場合は指標計算には使いません。

助言は区間ごとに1〜2件、全体には重複を除いて最大2件。

- H/Kが観測できてK > H×0.5の場合、膝の変化が相対的に大きいという根拠とともに「膝を深く曲げるより、股関節から折りたたむ意識を試す」。0.5は参考ルールで、医学的な境界値ではありません。
- 上体だけの根拠では、前傾/復帰が見えたことを示し「股関節から折りたたむ意識で動きを見比べる」と、関節が見える撮影位置の提案。未観測の股関節・膝が悪いという原因断定をしません。
- 全欠測、別方向、不正時刻、長い追跡途切れ、前傾不足などは割合を保留し、その理由と確認方法を表示。
- 骨盤を後方へ動かした量を直接測っていないため「お尻が引けていない」と判断しません。背中の丸まり、腰の反り、筋肉への効き、重量の適否、医学的安全性は未評価です。安全器具を外す提案はしません。

## お手本比較の式

保存済みのお手本スナップショットがあれば優先。なければ登録済みのお手本を初期選択します。一般的な確認ポイントへ明示的に切り替え可能。新参考評価の「計算時の比較基準」を表示し、保存後はその基準を維持します。

既存 `compareRep` の撮影方向・側・モデル（未設定はLite）・解析版・双方の股関節計測率80%以上・お手本の完成レップの条件を守ります。今回も角度による完成レップがある場合だけ、股関節最小、膝最小、体幹最大前傾、股関節観測幅を項目別に比較。欠測項目は保留。体幹動作候補だけをお手本の完成レップと比較したことにはしません。

`差（度） = 今回値 − お手本値`

`相対差（%） = 100 × 差（度） / お手本の股関節観測幅（rom）`

全項目の相対差は同じ観測幅を尺度にするもので、各関節角度の変化率や類似度ではありません。お手本の幅が5度未満・不明・0なら%保留。5度は安定した除算のための閾値。今回値・基準値・符号付き差・分母を表示します。

参考助言は、股関節最小が基準より5度超大きい／膝最小が5度超小さい／体幹最大が5度超小さい場合に、最初の該当項目を根拠に1件。基準との差が改善すべき欠点と確定したわけではありません。相反する「もっと倒す」「起こす」を同時に出しません。

## 一般的な参考基準と資料確認の限界

Good Form未登録でも、本Issueで提示された定性的なRDL確認ポイント「股関節から折りたたむ」「膝は軽く曲げる意識」と、取得できた前傾/復帰の根拠を表示します。万人共通の理想角度や未検証の参考角度レンジは実装しません。

## データ保護

DB v3/store構成は変更なし。元analysis、Good Formスナップショット、Blob、frames、ワークアウト日誌を新レイヤーで上書きしません。新解析では参考評価を生成、旧履歴では明示ボタンを押すまで再計算しません。保存ボタンで `feedbackReports` 配列へ版付きの別レポートを追記。従来レポートも保持し、再読み込み時は保存された最新レポートを表示して計算し直しません。別のお手本を選んでも既存referenceSnapshotを上書きしません。参考評価には最小限の比較値スナップショットを別保存します。

保存するのは方式版・定数・入力・観測品質/各場面平均と点数/時刻・項目差・助言・比較基準・元解析版/モデル/側/方向。新レポートに元動画/全Pose/全rowsを重複コピーしません。旧履歴にrows/必要な時刻がない場合は参考評価を保留し、補間・自動再解析しません。

## 検証とiPhone手順

`test-support/feedback-fixture.js` は開発者が生成した合成角度時系列。個人の動画/Poseから匿名化・抽出したものではありません。8区間、股関節61%・膝27%・上体100%という取得パターンで、新しい指標と少なくとも1件の助言を検証します。ユーザーの実動画自体は提供されておらず、同じ動画を再現したとは言えません。実機の最終受け入れ条件は未達（要利用者確認）です。

1. iPhone Safariで更新版を開き、ヘッダーv0.5.0を確認。従来8動作候補の動画を選び再解析するか、既存履歴から開いて「観測した動きからアドバイスを見る」。
2. 動作8区間を確認。前傾/復帰の証拠がそろう区間で「前傾から戻る動きの目安 ○%」と具体的な助言を確認。膝不足時に股関節主体の指標へ偽装しないことを確認。
3. 各区間の詳細を開き、観測幅・読み取れた割合・点数・時刻・場面別平均・式・実際の入力を確認。8回を確定したレップ数と誤認しないことを確認。
4. お手本なしでは一般的な確認ポイント、お手本ありでは計算時基準を確認。条件のそろう角度レップで基準/今回/符号付き差/%が表示されることを確認。動作候補しかない場合の角度比較は保留。
5. 保存→再読み込み。参考評価、元動画/骨格・重量/メモ・お手本・ワークアウト記録が保持されることを確認。比較基準を変えて計算し、以前のスナップショットを残したまま別レポートが保存されることを確認。
6. 正面・遮蔽・全欠測等では割合を作らず、理由と撮影案内が表示されることを確認。

未検証：実際の8候補動画での%/助言表示、Safari実機、実データでの閾値妥当性、指導者評価との整合、メモリ/容量不足。対象動画で上体の3場面/連続性が不足している場合は依然保留になり得ます。割合を出すためだけに証拠条件を無効化しません。
